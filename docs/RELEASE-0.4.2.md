# CertFlow 0.4.2 验收记录

本版本补充证书申请与续期的阶段进度、脱敏失败诊断，以及用于 Docker 桥接网络出站异常时的 NAS 主机网络部署方案。

## 验收范围

| 场景 | 结果 | 依据 |
| --- | --- | --- |
| 申请进度 | 通过 | `/api/state` 提供当前任务、固定阶段、阶段开始时间与有限量历史；浏览器每 3 秒同步状态，持续时间每秒更新，不显示不可靠的百分比或预计完成时间。 |
| 失败诊断 | 通过 | DNSPod 桥接错误优先使用白名单提示；常见 ACME、CAA 与 DNS 传播失败映射为固定文案；未知错误保持通用提示。原始客户端输出、域名验证值与凭据不写入页面或状态文件。 |
| 多任务与中断 | 通过 | 串行运行过程中可读取当前阶段与已完成数量；单任务失败不阻断后续任务；执行结束后清理运行中状态，保留本轮阶段记录。 |
| 页面交互 | 通过 | 隔离模拟器和 Chrome headless 验证运行中、失败、四个页面及 390px 手机视口；进度面板可收起，完成后可关闭，同一标签页刷新保持关闭，新任务自动重新显示。模拟器不访问真实 DNS 或 ACME。 |
| 主机网络配置 | 通过 | `compose.host-network.yaml` 与默认 Compose 合并后启用 host network、移除端口映射，并要求绑定指定 NAS IPv4；访问地址、管理密码和来源校验仍然生效。默认 Compose 继续使用桥接网络。 |
| NAS 网络诊断 | 通过 | 实际 DXP4800 上，旧容器的桥接网络访问 DNSPod 与 ACME 超时；NAS 主机网络下，DNSPod 只读域名查询与 ACME 目录访问成功。该检查不申请证书、不修改 DNS。 |
| 本地回归 | 通过 | `npm run check` 与 `npm test`：110 项中 108 通过、0 失败、2 项因 Windows 平台条件跳过。 |

阶段记录只表示 CertFlow 到达的程序边界。`等待 ACME 与 DNS 验证` 会持续到 lego 退出；本版本不展示未经验证的 TXT 创建时间、权威 DNS 传播比例或 CA 内部状态。

## 部署与数据

主机网络仅是遇到 Docker bridge 出站故障时的备用部署方式，详细配置见 [NAS Docker 部署指南](docker-nas.md#主机网络备用方案)。它与默认方案共用 `certflow-data` 数据卷。升级前应备份完整数据卷，并确保主机网络模式只绑定 NAS 的局域网地址。

镜像由 [GitHub Actions](https://github.com/qianshulab/certflow/actions/workflows/ci.yml)在 Windows / Linux 测试后构建与发布；Linux amd64 容器冒烟测试使用隔离网络，不替代真实域名签发验收。UGOS 管理页面在证书续期后仍需重新导入新证书。
